一、改动概述与交付物架构
----------------------------------------------------------------------------------------
1. application/package_builder.py:
   - 确定性 ZIP 打包 (build_deterministic_zip):
     * 固定文件入包字典序 (sorted lexicographical order)
     * 固定时间戳 (2026-01-01 00:00:00)
     * 固定 POSIX 权限属性 (0o100644 << 16)
     * 强力路径安全防御: 拦截含 '..'、绝对路径、驱动器号、符号链接 (Symlink)
     * 标配交付清单与文档: 打包 www/ 静态资源 (2162 文件) + manifest.json + README.md (离线运行指引与 SimpleHTTPServer 命令) + LICENSE (Apache-2.0)
     * 异步防阻塞事件循环: 使用 await asyncio.to_thread(build_deterministic_zip, ...) 调度至线程池，彻底杜绝 CPU/IO 压缩阻塞 asyncio 主事件循环，保护租约守护协程 (Heartbeat / Lease Guard) 正常续约。
   - 离线包校验器 (verify_offline_zip):
     * 校验 ZIP 自身 SHA256 摘要
     * 逐条审查 ZipEntry 路径安全性 (防 Zip Slip)
     * 必选文件存在性检查 (manifest.json, README.md, LICENSE)
     * 逐文件解压计算 SHA256 与清单 files[] 比对
   - 产物登记 (PackageBuilder._offline):
     * 登记 offline_zip 产物，media_type="application/zip"，存储键为 offline_package.zip
     * 产物 ID 同样走 artifact_id_for 内容哈希派生，保证幂等。

2. api/main.py (HTTP 下载与流式传输):
   - 端点 GET /api/v1/artifacts/{id}/download:
     * 鉴权增强: 校验 X-Owner-Id 归属实验，或持有该实验当前正在执行的活跃 job 租约 token (X-Lease-Token)。
     * 传输方式升级: 从全文件一次性读入内存重构为 StreamingResponse (64KB 块流式传输)。
     * RFC 7233 HTTP Range 支持:
       - bytes=start-end (标准前闭后闭分段，返回 206 Partial Content + Content-Range + Content-Length)
       - bytes=start- (从指定偏移到文件结尾)
       - bytes=-suffix (文件末尾 suffix 字节)
       - 越界请求返回 416 Range Not Satisfiable + Content-Range: bytes */total_size
     * 盘上哈希锁: 流式读取前对盘上目标文件进行异步流式 SHA256 计算 (asyncio.to_thread)，与数据库 artifacts.sha256 严格核对，不匹配立即返回 500 CONTENT_HASH_MISMATCH，文件不存在返回 404 ARTIFACT_FILE_MISSING。
     * 响应头返回 X-Content-SHA256、Accept-Ranges: bytes、Content-Length、Content-Disposition (指示附件下载文件名)。

3. apps/teacher-web (前端界面与下载落地):
   - components/DownloadButton.tsx: 新增可选 label 属性 (默认保持 "下载原生场景")。
   - components/ExperimentWorkspace.tsx: 接收 zipArtifact，在交付区域并列展示 "下载原生场景" 与 "下载完整离线实验包 (.zip)" 两个独立按钮。
   - App.tsx: 从 api.artifacts 列表提取 media_type="application/zip" 的产物作为 zipArtifact 传递给工作区。
   - 浏览器端下载采用 client.downloadVerified，流式拉取并在浏览器内存自主计算 SHA256 与登记值核对后触发落盘。

二、实测证据记录
----------------------------------------------------------------------------------------
1. 单元与微基准测试 (test_package_builder.py):
   - test_deterministic_zip_generates_identical_bytes_and_records_metadata:
     两次独立打包不同目录但相同内容的静态包，产生逐字节完全相同的 ZIP (SHA256 一致)。
   - test_deterministic_zip_contains_all_deliverables_and_passes_verification:
     验证 ZIP 内包含 manifest.json、README.md、LICENSE 与全部资源，verify_offline_zip 返回 ok=True。
   - test_verify_offline_zip_detects_tampered_payload_or_missing_file:
     测试篡改 ZIP 内某文件字节，verify_offline_zip 准确返回 ok=False (zip_sha256_mismatch / corrupted_zip)。
   - test_build_deterministic_zip_rejects_symlinks:
     测试构建过程遭遇符号链接立即抛出 DeliveryIntegrityError（无符号链接特权环境通过 mock 兜底保证真测不跳过）。
   - test_verify_offline_zip_rejects_unexpected_injected_files:
     测试向 ZIP 注入未在清单中声明的额外意外文件（如 backdoor.py），准确拦截并返回 ok=False, reason="zip_unexpected_files"。
   - test_verify_offline_zip_rejects_tampered_package_sha256_or_empty_readme:
     测试篡改清单中的 package_sha256 整包摘要，或 README.md 为空，准确拦截（zip_package_sha256_mismatch / readme_empty）。
   结果: 17 passed in 1.71s。
