一、问题定位与根因
--------------------------------------------------------------------------------
1. CandidateRepository.write() 冻结竞态 (P0):
   - 原 SQL: UPDATE experiment_candidates SET ..., status='editing', state_version=state_version+1 WHERE job_id=$1 AND state_version=$6
   - 缺陷: WHERE 谓词中未约束 status='editing'，而 freeze() 不自增 state_version。
   - 复现时序:
     Writer A 读到 state_version=0；
     Worker/Build 阶段调用 freeze()，status 变为 frozen，但 state_version 仍为 0；
     迟滞的 Writer A 执行 write(expected_version=0)，由于 state_version 匹配，SQL 更新成功；
     已冻结候选被静默写开并篡改，status 被重新置为 editing，旧验证结论失效。
   - 修复:
     在 write() 的 WHERE 谓词中增加 status = 'editing'；
     失败时 _explain_failure 严格区分：若已冻结或已发布，抛出 CandidateFrozen；
     freeze() 约束 status in ('editing', 'frozen') 并支持幂等重复冻结；
     bind_validation() 约束 status in ('editing', 'frozen') 且哈希一致；
     rebase() 约束 status in ('frozen', 'published') 才允许推进基线并重置为 editing。

2. Engine Host 内部接口路径与资源安全 (P0):
   - 缺陷: POST /export/offline_package 的 outDir 与 POST /verify/offline_package 的 dir 直接接受未校验的文件系统路径，存在 .. 穿越和绝对路径跳出风险；manifest.entry 未限定在 www/ 内；URL origin 比对使用 startsWith 前缀判断容易被伪造前缀绕过；请求 Body 缺乏大小限制。
   - 修复:
     新增 services/engine-host/src/security/path-sandbox.ts，实现 assertWithinSandbox() 白名单路径校验（防 ..、绝对系统路径跳出、符号链接逃逸）；
     /export 与 /verify 端点接入路径沙箱，越权直接拒回 HTTP 403 FORBIDDEN；
     readBody() 增加 10MB 大包限制，超限直接拒回 HTTP 413 PAYLOAD_TOO_LARGE；
     verifyOfflinePackage() 校验 manifest.entry 必须为相对路径且规范化后严格落在 www/ 目录下；
     请求监听器改用 new URL(req.url()).origin 进行严格全等比对。
