# hooks — React 钩子

**职责**：跨组件复用的状态逻辑。当前只有一个钩子——任务轮询，但它的三条硬约束值得单独成文。

## 内容（逐文件）

| 文件 | 行数 | 职责 | 关键符号 |
|---|---|---|---|
| `useJob.ts` | 56 | 任务状态轮询：**不重叠、终态即停、卸载即停**三条硬要求 | `useJob()` |

## 三条硬要求（实现纪律）

| 要求 | 为什么 |
|---|---|
| 不重叠 | 上一轮请求未回来不发下一轮——防"慢响应追尾"导致状态回退 |
| 终态即停 | succeeded / failed / cancelled 后停止轮询——不空转 |
| 卸载即停 | 组件卸载时取消——防内存泄漏与幽灵请求 |

## 与上下层的关系

- 依赖：[`../api/client.ts`](../api/README.md) 的 `job` 查询；被 [`../App.tsx`](../README.md) 使用。
- 轮询节奏与任务状态语义由后端 [`../../../../python/src/eduforge/api/README.md`](../../../../python/src/eduforge/api/README.md) 决定（阶段事件时间线）。

## 已知的坑与纪律

- 三条要求是防泄漏/防重复请求的关键——改动前先看 [`../../../../tests/python/test_teacher_web_e2e.py`](../../../../tests/python/test_teacher_web_e2e.py) 对进度与终态的断言。
- 轮询只在任务活跃期运行；新增任务态要同步"终态"判定，否则会永远轮询。
