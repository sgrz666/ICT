# EduForge 代码级实施方案

**目标文件：**`D:\codeplus\ICT\plan\26.10.15_EduForge_代码级实施方案.md`

**文档状态：**本文件于 2026-10-15 20:0x 由会话内附件落盘。**已验证的部分**：下文任务协议（`EditProposal`/`WorkOrder` 的 route 互斥约束）与透镜参数修改算法做过内存级测试；上游 Ray Optics 的 `package.json`、构建脚本入口、`IdealLens` 源码位置经网络核查。**尚未验证的部分**：完整应用、数据库、上游实验环境的集成运行一次都还没跑过；下文所有端口、依赖版本、命令均为待执行设计，不代表当前可用。

### 上游核查到的、与方案假设不一致之处（实测，非推断）

这些直接影响第一切片怎么做，先记在最前面：

1. **`ray-optics` 不在 npm registry 上**（`https://registry.npmjs.org/ray-optics` 返回 404），其 `package.json` 标 `"private": true`。
   ⇒ 复用方式只能是 **git 克隆源码**，不能 `npm install ray-optics`。V3 方案里"Node 模块"指的是它的 `build-node` 产物，不是可安装的包。
2. **版本与许可确认**：`name: ray-optics`、`version: 5.5.0`、`license: Apache-2.0`、`author: Yi-Ting Tu`。
   ⇒ `catalog/templates/optics/convex-lens/manifest.yaml` 里的 `engine_version: "5.5.0"` 与上游一致，不用改。
3. **`canvas@^2.11.2` 和 `sharp@^0.35.4` 在 `optionalDependencies` 里**，另有 `"mathquill": "github:Jutanium/mathquill-webpack"`、`"canvas2svg": "github:gliffy/canvas2svg"` 两个 GitHub 依赖。
   ⇒ 这是 Windows 上 npm 安装最容易卡住的一类组合：`canvas` 需原生二进制或预编译包，GitHub 依赖需 git+https 可达。**第一切片要先只验 `npm install` 能否装完**，再谈构建。`optionalDependencies` 装不上不会让安装失败，但会影响 `build-images` 等导出能力。
4. **构建入口是分段的，且有一个比"整站构建"轻得多的口子**：
   - `build-app` = `webpack --mode=production`（整站）
   - `build-simulator` = `webpack --mode=development`
   - `start` = `webpack serve --open simulator/ --mode=development`（本地开发服务器，**首版验证走这条**）
   - `build-node` = `webpack --config webpack.node.config.mjs`（Node 侧计算核心）
   - `build-scenes` / `build-pages` / `build-images` / `build-docs`
   - `build` = 六者全串 ⇒ **不要用它做首轮验证**
   - 测试入口：`test:scenes` = `node ./scripts/testScenes.mjs`，`test:sceneObjs`/`test:formula` 等走 jest

5. **本机环境实测**（2026-10-15，`py -0p` / `docker info` / `go version` 等真实输出）：

各目录里实际放什么、和上下层是什么关系，落盘时补一条说明：

* `source/upstream/` —— 只放**别人写的东西**：上游源码原样克隆，一个字节都不在这里改。改动一律发生在 `code/eduforge/` 里通过适配器读写。`upstream.lock.json` 是这里唯一的自有文件，记版本号、提交号、来源 URL、哈希和构建命令，升级/回退/定位"这坑是不是上游的"都靠它。上下层关系：`catalog/templates/*` 里的 `native.json` 是它的产物或手工子集，不是反过来。坑：它的 `node_modules` 与 `code/eduforge` 的依赖是两套，不要共用；克隆用 `--depth 1`，别把上游全部历史拉下来。
* `catalog/` —— 我们**整理过的、可信的实验元数据**：引擎能力清单（`engines/*.yaml`）和模板（`templates/<学科>/<名>/{manifest.yaml,native.json,lesson.md}`）。它是 Agent 唯一的知识来源，Agent 从这儿读到的东西才能当回事；上游 README、教师上传资料、REA 原始产物都不算，都只能进 `output/eduforge/research/`。坑：`manifest.yaml` 的 `native_units_per_unit` 是**这个模板**的坐标比例，不是引擎全局单位，改模板别串用。
* `code/eduforge/python/src/eduforge/domain/` —— 纯类型，不 import FastAPI、SQLAlchemy、LangGraph。它是最下层，被 `application`、`agent`、`api` 共同引用；反过来谁都不许被它引用。坑：`extra="forbid"` 是刻意的，模型多吐一个身份字段就要失败，不要为了"方便"改成 `ignore`。
* `code/eduforge/services/engine-host/` —— TS 侧唯一碰上游原生格式的地方，三个适配器各管一种格式。它与 Python 之间只走 HTTP，Python 不解释实验 JavaScript。坑：CircuitJS 的控制页与模拟器必须同源，所以预览必须本地起服务，不能嵌外部站点。
* `output/eduforge/` —— 跑出来的东西。`candidates/` 是未发布的候选，`artifacts/` 是验证通过后才准进；这个区分是发布门禁的实体形态。坑：这里的文件按任务覆盖会丢证据，命名要带 `job_id`/`revision_id`。
* `scripts/` —— 工作区唯一入口，见 7.4。坑：脚本不许自动升级上游依赖，不许删数据库和已有研究结果。

## 二、模块依赖与实际调用关系

### 2.1 代码依赖规则

```text
domain
  ↑
application ← agent
  ↑             ↑
api          entrypoints
  ↑
infrastructure 实现 domain/ports 中的接口

worker
  └── 调用 application/coordinator
        ├── AgentClient
        ├── EngineClient
        ├── ArtifactStore
        └── JobRepository
```

约束：

- `domain` 不导入 FastAPI、SQLAlchemy、LangGraph。
- `application` 依赖抽象接口。
- 数据库、HTTP 和文件存储在 `infrastructure` 实现。
- `agent` 生成和校验方案。
- `worker` 管理长时间执行及失败恢复。
- 浏览器运行实验，Python 不直接解释实验 JavaScript。

### 3.2 Python 核心协议

文件：`python/src/eduforge/domain/contracts.py`

```python
from typing import Annotated, Literal
from uuid import UUID

from pydantic import BaseModel, ConfigDict, Field, model_validator


class Contract(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        allow_inf_nan=False,
    )


class SetParameter(Contract):
    op: Literal["set_parameter"] = "set_parameter"
    entity_id: str = Field(min_length=1, max_length=80)
    parameter: str = Field(min_length=1, max_length=80)
    value: float


class SetView(Contract):
    op: Literal["set_view"] = "set_view"
    view_id: str = Field(min_length=1, max_length=80)
    visible: bool


Operation = Annotated[
    SetParameter | SetView,
    Field(discriminator="op"),
]


class EditProposal(Contract):
    route: Literal["config", "code"]
    operations: list[Operation] = Field(
        default_factory=list,
        max_length=32,
    )
    code_task: str | None = Field(
        default=None,
        min_length=1,
        max_length=4000,
    )

    @model_validator(mode="after")
    def check_route(self):
        if self.route == "config":
            if not self.operations or self.code_task is not None:
                raise ValueError("config requires operations only")
        elif (
            self.operations
            or not self.code_task
            or not self.code_task.strip()
        ):
            raise ValueError(
                "code requires a non-empty code_task only"
            )
        return self


class PlannerRequest(Contract):
    job_id: UUID
    experiment_id: UUID
    base_revision: UUID
    prompt: str = Field(min_length=1, max_length=4000)
    feedback: list[str] = Field(
        default_factory=list,
        max_length=32,
    )


class WorkOrder(Contract):
    job_id: UUID
    experiment_id: UUID
    base_revision: UUID
    engine_id: Literal[
        "ray_optics",
        "myphysicslab",
        "circuitjs",
    ]
    proposal: EditProposal
```

这里有两个不同层次：

- `EditProposal` 是模型输出，只表达修改建议。
- `WorkOrder` 是服务器构造的工作单，附带可信任务、实验和版本标识。

模型不负责决定用户身份、实验归属和基础版本。

首版结构修改通过代码定制路径完成；后续需要高频增加器材时，再增加有明确类型的 `add_entity` 操作。

`engine_id` 的三个取值是协议层面的完备设计，**首批只有 `ray_optics` 有真实适配器**；另两个值在 `policy.py` 未登记能力前会被拒。

### 4.2 LangGraph 规划图

文件：`python/src/eduforge/agent/graph.py`

```python
from typing import Any, Protocol, TypedDict

from langgraph.graph import END, START, StateGraph

from eduforge.domain.contracts import (
    EditProposal,
    PlannerRequest,
    WorkOrder,
)


class PlanningState(TypedDict, total=False):
    request: PlannerRequest
    context: dict[str, Any]
    evidence: list[dict[str, Any]]
    proposal: EditProposal
    work_order: WorkOrder


class PlanningServices(Protocol):
    async def load_context(
        self,
        request: PlannerRequest,
    ) -> dict[str, Any]: ...

    async def retrieve(
        self,
        prompt: str,
        context: dict[str, Any],
    ) -> list[dict[str, Any]]: ...

    async def draft(
        self,
        request: PlannerRequest,
        context: dict[str, Any],
        evidence: list[dict[str, Any]],
    ) -> EditProposal: ...

    def authorize(
        self,
        request: PlannerRequest,
        context: dict[str, Any],
        proposal: EditProposal,
    ) -> WorkOrder: ...


def build_planning_graph(services: PlanningServices):
    async def load_context(state: PlanningState):
        context = await services.load_context(state["request"])
        return {"context": context}

    async def retrieve(state: PlanningState):
        evidence = await services.retrieve(
            state["request"].prompt,
            state["context"],
        )
        return {"evidence": evidence}

    async def draft(state: PlanningState):
        proposal = await services.draft(
            state["request"],
            state["context"],
            state["evidence"],
        )
        return {"proposal": proposal}

    def authorize(state: PlanningState):
        work_order = services.authorize(
            state["request"],
            state["context"],
            state["proposal"],
        )
        return {"work_order": work_order}

    graph = StateGraph(PlanningState)

    graph.add_node("load_context", load_context)
    graph.add_node("retrieve", retrieve)
    graph.add_node("draft", draft)
    graph.add_node("authorize", authorize)

    graph.add_edge(START, "load_context")
    graph.add_edge("load_context", "retrieve")
    graph.add_edge("retrieve", "draft")
    graph.add_edge("draft", "authorize")
    graph.add_edge("authorize", END)

    return graph.compile()
```

`Protocol` 中的省略号是接口声明，实际实现放在 `agent/services.py`。

各方法固定职责：

| 方法 | 实现内容 |
|---|---|
| `load_context` | 读取指定基础版本，加载可信模板及能力清单 |
| `retrieve` | 获取相关参数、接口、教学依据和错误说明 |
| `draft` | 请求模型生成 `EditProposal`，执行 Pydantic 校验 |
| `authorize` | 校验对象、参数、范围、视图、代码修改范围，构造工作单 |

此图执行一次短规划或修复规划后返回。长任务的阶段、重试和恢复由数据库任务管理，避免依赖 Runtime 请求结束后的后台执行。

LangGraph 的节点与状态组织方式依据[官方 Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)。

### 4.4 Ray Optics 原生数据修改

文件：`services/engine-host/src/adapters/ray-optics/patch.ts`

```typescript
import type { SetParameter } from "@eduforge/contracts";

type RayObject = {
  type: string;
  name?: string;
  focalLength?: number;
  [key: string]: unknown;
};

type RayScene = {
  version: number;
  objs: RayObject[];
  [key: string]: unknown;
};

type LensBinding = {
  entity_id: string;
  native_type: "IdealLens";
  parameter: "focal_length_cm";
  min: number;
  max: number;
  units_per_unit: number;
};

// 按 name 定位对象。不用数组下标：上游 Scene.reorderObj 会重排 objs，
// Editor 拖动时对 Handle 调 unshiftObj 插到队首，removeObj 让后续对象前移。
function findEntity(scene: RayScene, entityId: string): number {
  const hits = scene.objs
    .map((o, i) => ({ o, i }))
    .filter(({ o }) => o.name === entityId);

  if (hits.length === 0) throw new Error("ENTITY_NOT_FOUND");
  if (hits.length > 1) throw new Error("ENTITY_AMBIGUOUS");
  return hits[0].i;
}

export function setRayParameter(
  scene: RayScene,
  edit: SetParameter,
  bindings: readonly LensBinding[],
): RayScene {
  const binding = bindings.find(
    item =>
      item.entity_id === edit.entity_id &&
      item.parameter === edit.parameter,
  );

  if (!binding) {
    throw new Error("PARAMETER_NOT_SUPPORTED");
  }

  if (!Number.isFinite(edit.value)) {
    throw new Error("VALUE_NOT_FINITE");
  }

  if (edit.value < binding.min || edit.value > binding.max) {
    throw new Error("VALUE_OUT_OF_RANGE");
  }

  if (
    !Number.isFinite(binding.units_per_unit) ||
    binding.units_per_unit <= 0
  ) {
    throw new Error("INVALID_UNIT_MAPPING");
  }

  const result = structuredClone(scene);
  const target = result.objs[findEntity(result, binding.entity_id)];

  if (!target || target.type !== binding.native_type) {
    throw new Error("ENTITY_TYPE_MISMATCH");
  }

  target.focalLength = edit.value * binding.units_per_unit;

  return result;
}
```

版本判断不放在这里。原稿写的 `if (scene.version !== 5) throw` 已删——上游 `Scene.loadJSON` 自己处理版本（无 `version` 则迁移，字符串或大于 `DATA_VERSION` 则置 `scene.error` 拒绝，小于则迁移），适配器硬编码会在上游 bump `DATA_VERSION` 时误伤合法场景。正确做法是改完之后调用 `loadJSON` 并读回 `scene.error`。

示例行为：

```text
教师输入：焦距改成 15cm
模型输出：focal_length_cm = 15
模板比例：1cm = 10 个场景单位
原生结果：focalLength = 150
原始版本：保持不变
```

`IdealLens` 和 `focalLength` 已通过上游源码核查。[源码位置](https://github.com/ricktu288/ray-optics/blob/master/src/core/sceneObjs/glass/IdealLens.js)

这里操作的是序列化数据，随后仍需使用上游 `Scene.loadJSON()` 加载并验证。

**原稿的三个"落盘待核"问题，本机实测已回答**（详细输出在 `output/eduforge/reports/slice1-rayoptics-probe.json` 与 `source/upstream/upstream.lock.json`）：

1. **版本字段**：`DATA_VERSION = 5`，但上游有迁移与拒绝两套逻辑 ⇒ 不硬编码，交给 `loadJSON`。
2. **`focalLength` 的单位与符号**：上游无单位系统，坐标是纯场景单位，所以 `units_per_unit` 完全是我们的约定，且必须锁 `lengthScale: 1`；`focalLength > 0` 会聚、`< 0` 发散，本模板（凸透镜）要拒非正值，凹透镜应是另一个模板。上游默认值 100，与模板 `initial: 10` 在 1cm=10 单位下自洽。
3. **对象顺序稳定性**：**不稳定，下标绑定作废**，改为按 `name` 绑定。实测 `reorderObj(1,0)` 后 `objs[0]` 由透镜变成点光源；`unshiftObj(Handle)` 后 `objs[0]` 是 Handle、透镜到 index 2。

### 4.6 Deep Agents 代码定制

```python
import asyncio
from collections.abc import Callable

from deepagents import create_deep_agent
from langchain_opensandbox import OpenSandboxBackend
from opensandbox import SandboxSync


EXPORT_PATHS = [
    "/workspace/src/lesson.ts",
    "/workspace/src/controls.ts",
]


async def customize(
    *,
    model,
    create_sandbox: Callable[[], SandboxSync],
    input_files: list[tuple[str, bytes]],
    instruction: str,
):
    sandbox = await asyncio.to_thread(create_sandbox)

    try:
        backend = OpenSandboxBackend(
            sandbox=sandbox,
            timeout=60,
        )

        await asyncio.to_thread(
            backend.upload_files,
            input_files,
        )

        agent = create_deep_agent(
            model=model,
            backend=backend,
            tools=[],
            system_prompt=(
                "你负责修改已有教学实验的包装与交互。"
                "根据提供的接口完成任务。"
                "最终交付文件为 src/lesson.ts 和 src/controls.ts。"
                "请说明完成内容和验证结果。"
            ),
        )

        async with asyncio.timeout(300):
            await agent.ainvoke(
                {
                    "messages": [
                        {
                            "role": "user",
                            "content": instruction,
                        }
                    ]
                },
                config={"recursion_limit": 30},
            )

        return await asyncio.to_thread(
            backend.download_files,

        )

```

配套实现要求：

- `sandbox_factory.py` 创建受限任务环境，并预装固定工具链。
- 模型在可信进程调用，真实模型密钥不写入任务文件。
- `tools=[]` 表示没有额外业务工具；框架内置文件与命令能力由沙箱后端承接。
- 最终只收集明确列出的文件，并检查下载结果。
- 验证使用新的沙箱，重新注入可信测试和依赖。
- 不采用 Agent 在编码环境中改写的测试结果作为发布依据。

适配包的导入路径与生命周期依据[当前集成文档](https://pypi.org/project/langchain-sandbox-opensandbox/)，仍需对锁定版本进行真实集成测试。

```python
    experiment_id: UUID
    base_revision: UUID
    prompt: str = Field(min_length=1, max_length=4000)


class JobAccepted(Contract):
    job_id: UUID
    status: str
```

路由文件：`python/src/eduforge/api/routes/jobs.py`

```python
from typing import Annotated
from uuid import UUID

from fastapi import APIRouter, Header, Request

from eduforge.domain.contracts import (
    CreateJobRequest,
    JobAccepted,
)


router = APIRouter(prefix="/api/v1/jobs", tags=["jobs"])


@router.post("", status_code=202, response_model=JobAccepted)
async def create_job(
    body: CreateJobRequest,
    request: Request,
    idempotency_key: Annotated[
        UUID,
        Header(alias="Idempotency-Key"),
    ],
):
    service = request.app.state.job_service
    owner_id = request.state.owner_id

    return await service.submit(
        owner_id=owner_id,
        idempotency_key=idempotency_key,
        body=body,
    )
```

`job_service.submit()` 在事务中完成校验和入队，返回后由独立 Worker 执行。

本地版本由入口注入固定开发身份；云端由认证层注入身份。路由不从请求正文接受 `owner_id`。

### 4.8 数据库领取任务

文件：`python/src/eduforge/infrastructure/db/repositories.py`

核心 SQL：

```sql
WITH candidate AS (
    SELECT id
    FROM jobs
    WHERE
        status IN ('queued', 'running')
        AND next_run_at <= now()
        AND (
            lease_until IS NULL
            OR lease_until < now()
        )
    ORDER BY created_at
    FOR UPDATE SKIP LOCKED
    LIMIT 1
)
UPDATE jobs AS job
SET
    status = 'running',
    lease_token = :lease_token,
    lease_until = now() + interval '90 seconds',
    updated_at = now()
FROM candidate
WHERE job.id = candidate.id
RETURNING job.*;
```

执行规则：

- 每 30 秒续租。
- 更新阶段和发布结果时必须带当前 `lease_token`。
- 超时后由新 Worker 从保存的阶段恢复。
- 外部构建使用 `job_id + stage + attempt` 作为操作幂等键。
- 取消任务后回收沙箱，禁止继续发布。
- 首版执行并发为 1。

### 5.1 独立科学参考代码

文件：`python/src/eduforge/validation/scientific/optics.py`

```python
import math


def thin_lens_reference(
    focal_length_cm: float,
    object_distance_cm: float,
) -> dict:
    f = focal_length_cm
    u = object_distance_cm

    if not math.isfinite(f) or not math.isfinite(u):
        raise ValueError("inputs must be finite")

    if f <= 0 or u <= 0:
        raise ValueError("convex-lens inputs must be positive")

    if math.isclose(u, f, rel_tol=1e-9, abs_tol=1e-9):
        return {
            "image_distance_cm": None,
            "magnification": None,
            "image_kind": "at_infinity",
        }

    v = f * u / (u - f)

    return {
        "image_distance_cm": v,
        "magnification": -v / u,
        "image_kind": "real" if v > 0 else "virtual",
    }
```

例如：

```python
result = thin_lens_reference(10, 30)

assert math.isclose(result["image_distance_cm"], 15)
assert math.isclose(result["magnification"], -0.5)
assert result["image_kind"] == "real"
```

这份代码只负责参考计算。

适配器的观测值来自实际仿真：例如光线交点、模型变量或电路采样。不能将相同参考公式同时放在观测端，否则会形成自我验证。

**注意适用条件**：`thin_lens_reference` 是理想薄透镜模型，上游 Ray Optics 的 `IdealLens` 也是理想透镜，两者可比；但若改用几何面（`GeometricOptic`）或真实玻璃折射率对象，比较就不成立。验证报告要记录用的是哪个对象类型。

### 6.3 AgentArts 入口

文件：`python/src/eduforge/entrypoints/entrypoints/agentarts.py`

```python
from agentarts.sdk import AgentArtsRuntimeApp

from eduforge.agent.bootstrap import build_planner
from eduforge.domain.contracts import PlannerRequest


app = AgentArtsRuntimeApp()
planner = build_planner()


@app.entrypoint
async def handler(payload: dict) -> dict:
    request = PlannerRequest.model_validate(payload)

    result = await planner.ainvoke(
        {"request": request},
        config={"recursion_limit": 12},
    )

    return result["work_order"].model_dump(mode="json")


if __name__ == "__main__":
    app.run()
```

本地 Agent 入口和 AgentArts 入口调用同一个 `build_planner()`。

### 7.2 必须覆盖的自动测试

**协议与策略：**

- 正常参数修改。
- 空操作、错误路线组合。
- NaN、Infinity、越界值。
- 未登记的对象、参数和视图。
- 模型输出额外身份字段。
- 不支持的上游场景版本。

**适配器：**

- 单位换算。
- 修改不污染原始数据。
- 对象索引与原生类型一致。
- 保存后重新加载结果相同。
- 三种环境各自原生格式往返。（首批只跑 Ray Optics 一项）

**任务与发布：**

- 相同幂等请求只产生一个任务。
- 同一幂等键不同内容被拒绝。
- 两个 Worker 不同时领取同一有效租约。
- 租约过期恢复、旧 Worker 无权发布。
- 并发修改产生版本冲突。
- 取消和验证失败不会发布候选文件。

**真实实验：**

- 欧姆定律与串并联数值。（后移）
- 单摆周期及无阻尼能量变化。（后移）
- 理想薄透镜实像、虚像与焦点边界。
