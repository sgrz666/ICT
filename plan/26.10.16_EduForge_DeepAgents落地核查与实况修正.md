## 2. 核查中另发现的 9 项它没提到的缺陷（本轮已修）

1. **验证结论不随场景失效**：改完 `native_data`/`views_config` 不清报告，而 build/publish 只在报告缺失时才补验 → 「验过 → 再乱改 → 发布」能过。
2. **假成功发布**：`conn=None` 时整段事务被跳过却仍返回 `status="published"`；工具路径的验证结果从不写 `validation_reports`。
3. **恒真门禁**：`worker/steps.py` 的 `base_untouched = (base != result) or True`，永真，使 `validation/README.md` 宣称的那道闸门实际不存在——而引擎早就在 `main.ts:60` 算出了正确字段，是被 Python 覆盖掉的。
4. **8 项工具完全不经过策略层**：`experiment_tools` 只 import `load_template`，从不 import `authorize`。模型可指名任意 `entity_id`/`parameter`/`view_id` 与任意数值，只剩上游 `loadJSON` 与事后验证兜底。**这条是接真实模型前的头号必修**——正则代理不会主动利用它，模型一定会试。
5. **身份仍可由模型填**：`owner_id` 是 `OpenExperimentInput` 的带默认值入参（且该类没继承 `Contract`，`extra="forbid"` 保护缺席），`langchain_tools.py` 把它暴露为模型可见参数，`service.py` 直接写进 `experiments.owner_id`。
6. **「自愈」是伪造出来的**：patch 被拒时合成一条 `expected=50.0` 的验证记录，再被一段硬编码分支精确匹配、回填 clamp 后的值；教师要 60cm、系统交付 `ctrl.max` 并报 `passed`。
7. **交付字节无完整校验**：只记 `native.json` 的 sha256，离线包整目录（真正会出事的 `www/` 资源）不参与哈希。
8. **候选 id 非确定**：工具层每次 `uuid4`，重试即产生新候选 + 孤儿目录；Worker 侧的 `derived_id` 已是正确做法，两处不一致。
9. **构建/发布倒序 + 最终候选不入库**：`publish_revision` 先发生、`build_package` 排在最后一个节点；而发布内部又会自动构建并在提交后清空 `built_artifacts`，于是最后那次构建产生的候选与产物行**从未登记**，交付出去的 revision id 在 `experiment_revisions` 里不存在。

另记两项未修（如实标 pending）：**租约从不续期**（`renew_lease` 零调用者、`LeaseManager` 未接线且调的是不存在的 `heartbeat`；默认 90s，真模型多轮必然超时）与**无重试记账**（`attempt`/`next_run_at` 从不移写）。

## 3. 本轮实施内容

- **凭证实况**：注册表/进程环境里**不存在** `deepseek` 变量（`scripts/eduforge.ps1` 找的就是它，故此前脚本一直走无 key 分支）；`LLM_API_KEY` 对 `api.deepseek.com` 返回 401 invalid；`DASHSCOPE_API_KEY` 经 `compatible-mode` 可用但未采用。本轮由用户临时提供 DeepSeek key 完成真模型实测，并声明事后轮换。key 全程只经环境变量传递，未写入任何仓库文件。
- **依赖**：新增 `deepagents==0.7.26`、`langchain-openai`、显式 `langchain-core`。`uv.lock` 实测新增 26 包、`langgraph` 不动、唯一降级 `tenacity 9.1.4`。`langgraph-checkpoint-postgres` **本轮未加**（asyncpg 与 psycopg3 双驱动、且没有能证明其价值的用例；重启安全目前由 job 绑定 + 派生 id 满足），留待需要跨进程恢复执行上下文时再开设计。
- **执行核心**：`agent/deepagents_runtime.py`（`create_deep_agent` + `StateBackend` + 提示词/SKILL 注入 + trace 抽取）、`agent/deepagents_planner.py`（`PlannerPort` 实现，提案**由成功的工具调用派生**而非模型自述）、`agent/tool_registry.py`（模型可见 6 项；`build_package`/`publish_revision` 不进模型；异常转 `isError` 观察）、`agent/fake_model.py`（脚本化假模型，与真模型同一条装配路径）、`agent/prompts/experiment_agent.md`。删除 `agent/tool_agent.py`，其正则原样保留为 `tests/python/_regex_baseline.py` 对照组。`agent/model.py` 由「零运行时引用」转正为唯一模型工厂，端点与模型名配置化，`planners.py` 也从它取值。
- **收敛**：工具层发布改为委托 `application/publication.py` → `JobRepository.publish`（新增 `close_job`，使一个 job 可连续提交多个版本而终态只落一次）；`derived_id` 从 `worker/steps.py` 上移到持久层供两处共用；`policy.py` 抽出 `authorize_operation` 供 Worker 与工具层同源使用；`agent/__init__.py` 不再再导出会引 `experiment_tools` 的模块（此前存在 `agent ↔ experiment_tools` 循环导入）。
- **Worker 入口**：`--planner model|deep|static`；`scripts/eduforge.ps1` 无 key 时**不再**自动注入 `--planner-static-focal 15`，改为拒绝启动并说明，只有显式 `EDUFORGE_ALLOW_STATIC_PLANNER=1` 才进链路验证模式。

## 4. 实测结果

- `uv run pytest`：**103 收集 / 102 通过 / 1 SKIPPED**（无 key 的真模型用例）。计数只写在 `catalog/engines/ray-optics.yaml` 的 `test_totals`。
- `npx vitest run`（engine-host）：**54 通过**，本轮未触碰 TS 侧。
- 真模型组合任务（`deepseek-flash`，temperature 0）：**7 次自主工具往返**，含一次「首次检索未命中 → 自己换查询词重试」；最终场景 `focal_length_cm=15.0`、`object_distance_cm=30.0`；`image_plane_matches_reference` 的 `observed=30 / expected=30` 来自真实光线追踪，与薄透镜 `v = fu/(u−f)` 的独立参考一致；库里只多出 `open_experiment` 建的基线版本，job 仍 `running`（模型确实没有发布权）。证据：`output/eduforge/reports/agent-deepagents-real.json`。
- 负向门禁全部按预期失败：超量程 60cm 被策略拒绝且不换值；未登记视图/对象被拒；改内容后旧验证结论不作数（报告行数可证重验发生）；无库连接时发布抛错而非回报成功。
