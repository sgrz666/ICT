## 还没配的（`rea doctor` 现状：healthy: false）

引擎缺失，不是安装坏了。缺的都是外部反编译器，REA 不会自动下载：

* Hopper → `rea setup` 可选安装，或设 `HOPPER_LAUNCHER_PATH`
* Ghidra → 设 `GHIDRA_INSTALL_DIR` 指向解压好的 Ghidra 12.1.x（Windows 上官方标 experimental）
* IDA → 设 `REA_IDA_MCP_CONFIG`；Windows 原生分析走 IDA 或 Kuna
* JADX → 设 `REA_JADX_MCP_JAR`（要自备 jadx-headless-mcp 0.7.1 JAR，Android 用）
* JEB → 设 `REA_JEB_MCP_URL`

所以现在的可用面：JS/Electron 静态重建、网页 bundle 抓取分析、制品(archive)清点、EVM/WASM 等不需要外部引擎的部分。原生二进制和 APK 要先装对应引擎。

另外按选择没运行 `rea setup`：它只写 Claude Code / Cursor / Gemini CLI / Claude Desktop / Codex 的用户级配置并安装 REA skill 文件，`rea doctor` 里 `skill:identity` 和各 `registration:*` 的 config_drift 就是这个原因。要接这些客户端时再跑 `rea setup --dry-run` 看计划。

## 用法备忘

```bash
rea --help                                  # 全部子命令
rea doctor                                  # 就绪检查
rea analyze-javascript-application <目录>    # 静态重建 JS/Electron 应用
rea analyze-web-bundle                      # 抓页面 bundle 做静态分析
rea inspect-artifact / decompile / trace    # 需要对应引擎
--format json|yaml|md|toon                  # 输出格式；--filter-output a,b.c 取子字段
--llms                                      # 给模型读的清单
rea update                                  # 全局安装时自更新
```

注意：`--token-limit` 不能和 `--format json` 一起用（会报 UNSUPPORTED_OUTPUT_COMBINATION），要截断就用 `--filter-output`。
