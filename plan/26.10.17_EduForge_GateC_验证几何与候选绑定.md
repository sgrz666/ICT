> 触发：指令 §2 Gate C。**本轮只推进 C.1 与 C.2**，并且把一条「假绿灯」换成了「真拒绝」——
> 因此 Gate C **未闭环**，本文写清楚已经落成什么、量具极限在哪、还差什么。
> 分支：`main`（用户 2026-10-17 定口径：以后所有改动直接落 main，不建分支）。起点 `0573ea1`。

## 1. 本轮实施（C.1 + C.2）

### C.1 验证报告绑定候选、来源与剖面

- `validation/reports.py`：`Check` 增加 `source`（证据来源）、`profile`（成立剖面）、
  `status`（`pass`/`fail`/`na` 三态）、`tolerance`（容差依据）、`decisive`（是否参与结论）；
  `ValidationReport` 增加 `candidate_id`/`content_hash`/`engine_version`/`profile`；
  `finalize()` 改为：**任一 `fail` → failed；任一决定性 `na` → inconclusive；全 `pass` → passed**。
  `passed` 与 `status` 不一致时构造即报错，防止报告与结论各说一套。
- 迁移 `0003_validation_report_binding.sql`：`validation_reports` 加 `candidate_id`/`content_hash`/
  `engine_version`/`profile` 四列，全部可空、不改写老行（`Publisher.record_report` 现在写这些列——
  只存在 checks JSON 里的绑定等于没有绑定）。
- 工具层 `run_validation` 新增**只对后端开放**的 `final` 参数（`RunValidationInput` 不含它，模型碰不到）：
  `final=True` 时先把候选从库里**重新读回来**、再 `freeze()`，然后才出结论。Worker 的 validating 阶段用它。
  这条存在理由是「最终验证必须验的就是被冻结被发布的那一版」，不能吃进程内缓存。
- `Chain.validating` 的 payload 现在区分 `failed_checks`（观测反驳）与 `unverifiable_checks`（观测不到）——
  两者都拦得住发布，但混在一起会让人以为物理不成立。

### C.2 虚像与无穷远改为独立几何证据

- 引擎侧新增 `beamGeometry()`（`services/engine-host/src/adapters/ray-optics/upstream.ts`）：
  拿 7 块屏的**实测光斑二矩宽度**做线性拟合，给出四态
  `real`（两侧宽度收敛，交点即像面）/`virtual`（宽度单调增大且反向延长交点在入射侧）/
  `collimited`（宽度全程变化 < 15%）/`inconclusive`（附理由），
  并一并交出 `resolution_cm`（最小屏间距的一半）、`array_span_cm`、`fit_r2`、
  `resolvable_max_abs_distance_cm`。`Probe` 加了 `centroid_units`/`x_units`/`extent_units`。
- **孔径截断判据**：探测器均匀照亮时 rms 的理论上限是 `len/√12`；最窄读数超过它的 90%
  就说明光斑比屏还大，发散与平行在这块屏上根本读不出来 → 判 `inconclusive`，
  **不许把「看不出变化」说成「测得平行」**。
- `validation/policies.py`：删掉 `virtual_image_valid: u < f` 与 `focal_parallel_beams: abs(f-u)<1e-4`
  这两条公式恒真判据；新增 `beam_geometry_agrees`/`beam_geometry_resolved`/`beam_parallelism_observed`。
  实像工况另有决定性观测（屏位 + 光斑是否真聚焦），所以那里的几何 `na` 标为非决定性；
  虚像与无穷远没有别的量具，那里的 `na` 直接决定结论。
  顺带修掉 `image_plane_matches_reference` 的 `abs(...) < 1e-9` 假精确，改为「落在屏分辨率 2cm 内」。

## 2. 实测结果（本机，无 Docker；引擎为真实上游 bundle）

| 工况 | 引擎实测几何 | 报告结论 | 含义 |
|---|---|---|---|
| f=15、u=30（实像 v=30） | `real`，交点 30.86cm，R²=0.92 | **passed** | 与独立参考差 0.86cm ≤ 分辨率 2cm，且最窄屏 rms 0.92 真聚焦 |
| f=12、u=30（实像 v=20） | `inconclusive`（右侧两点拟合 R²=0.78） | **passed** | 靠屏位与聚焦两项决定性观测；几何作非决定性证据，如实标 `na` |
| f=30、u=30（u=f） | `collimated` 前置判定 → 实际落在 `apertureLimited` 分支 | **inconclusive** | 7 屏读数 rms 67.76 ≈ 均匀上限 69.3（98%），光斑铺满探测器，测不出平行度 |
| f=40、u=30（虚像 v=−120） | 同上，孔径截断 | **inconclusive** | 旧实现此处凭 `u<f` 报 passed，现为拒绝 |
| f=50、u=10（虚像 v=−12.5） | 同上（宽度只变 5.2%） | **inconclusive** | 期望「近虚像可测」被实测否证：发散角太大反而全部溢出探测器 |
| f=5（v=6 → 屏阵列之外） | `inconclusive` | **failed** | `spot_is_actually_focused` 反驳（最窄 rms 44.6 > 15） |

- 全量：`uv run pytest -q` **exit 0**，125 收集 / 124 通过 / 1 SKIPPED（真模型无 key）；
  `vitest run` **67 passed（10 files）**，含新增 `beam_geometry.test.ts` 13 项。
- 中途一次自我纠正：我一开始给「近虚像」写了应当通过的断言，实测发现 7 格屏在读数饱和时
  连 5cm 外的虚像都测不出来——**改的是判据与量具，不是改断言迁就绿灯**。

## 3. 本轮刻意收紧带来的行为变化（不是回归）

`test_chain_worker.py` 里两条旧用例（`test_chain_focal_parallel_beams_at_infinity`、
`test_chain_virtual_image_valid`）与 `test_agent_tools_acceptance.py` 的边界用例，此前断言的是
「虚像/无穷远任务发布成功」。那个成功建立在公式自证上，现已不存在，因此改为断言：

- `test_chain_far_virtual_image_is_refused_with_stated_instrument_limit`：任务可见失败
  （`VALIDATION_NOT_PASSED`）、head 不动、无产物；
- `test_chain_parallel_beam_must_be_measured_not_assumed`：只允许两种结局——
  实测到平行度而发布，或测不出来而拒绝，**不允许凭公式发布**。

## 6. 实况（同日第二轮，起点 `32b1883`）：§4 第 1 条量具缺口已补，虚像/无穷远改为凭实测发布

上面 §2 的表与 §3、§4 第 1 条写的是**第一轮当时的真实状态**，按历史现场理解，不改写。
本轮把量具补上了，缺口关闭：

- **观测副本**（`buildProbeScene`）：探测器半高 120→1200 场景单位，`binSize` 保持 2 不变
  （只加 bin 数，宽度分辨率仍是 0.2cm）；在透镜面加一块 `Aperture`，透光孔与透镜口径同宽。
  加光阑不是装饰：只加宽屏时二矩被「没经过透镜」的直光扇主导，实测各屏 rms 全都 ~450–520 且不随
  位置变化。控制组（f=50、u=30，参考 v=−75.0cm）：有光阑交点 −75.0cm、R²=1.000、σ=0.002；
  无光阑交点 −227.3cm、R²=0.933、σ=0.238。**两个都"判出了虚像"**，所以判据不能只看 `kind`。
- **判据改为带不确定度**：`beamGeometry` 交出 `slope_stderr_units_per_cm`/`vertex_stderr_cm`/
  `clipped_screens`；准直判据由「相对变化 < 15%」（挑的常数）改为 `|slope| ≤ 2σ_slope`（算出来的）；
  实像外推与虚像反向延长的容差统一为 `max(2×屏定位分辨率, 3×外推交点标准误)`，
  删掉 `PARALLEL_REL_CHANGE` 与虚像的「10×分辨率」。Python 侧**重算**这两条不等式，不采信引擎给的态。
- **15 个工况逐条实测全部判出**，与薄透镜独立参考最大偏差 0.8cm（像点落在两屏之间的 V 形工况）；
  外推工况最大偏差 0.6cm。上一轮"测不出来"的三条：f=40 → −119.6cm（参考 −120）、
  f=50/u=10 → −12.5cm（参考 −12.5，σ=0.005）、u=f → 各屏宽度完全一致。
- **行为变化（松紧都在明处）**：`test_chain_worker.py` 的两条用例从「必须拒绝」改为
  `..._publishes_on_measured_divergence` / `..._publishes_on_measured_parallelism`（断言 succeeded、
  revision 前进、有产物）；`test_physics_boundary_infinite_and_virtual_image` 不再接受
  "测不出来所以 inconclusive 也算对"。`test_validation_failure_blocks_publish`（f=5）仍失败——
  几何证据来自观测副本，但教师看到的交付屏上不成像，`spot_is_actually_focused` 照样反驳。
- 计数：vitest 67→**70**（`beam_geometry.test.ts` 13→16 项，含观测副本构造与光阑控制组），
  pytest 仍 125（改名两条，未增删）。
- 新缺口（如实登记，属 §4 第 1 条的收尾而非新账）：观测副本只服务于**验证**，

## 7. 实况（同第三轮，起点 `c57f059`）：§4 第 3–4 条里的 C.4 已落地，C.5 只做了一半

本轮把"发布的是哪一份字节"这条线收到一个入口上，并顺手抓到一个真实漏检：

- **三处不一致**：① `Chain.building` 传 `export_offline_zip=False`、`Chain.packaging` 自己手写落盘与
  artifacts 登记 ⇒ 整条生产链从来没有离线运行包；② 工具层与 Worker 各拼一份 artifacts、各算一次 id；
  ③ 引擎写 `offline_package/manifest.json` 的交付元数据（入口/引擎版本/是否需要随包静态服务/许可）
  被 Python 的逐文件哈希表**同路径覆盖**，最终包里的清单连"怎么打开这份包"都不记得。
- **修法**：新增 `application/package_builder.py`（216 行）作为唯一写盘与登记入口——写前先比、不同则重写、
  写完回读核对（不一致 → `DeliveryIntegrityError` → Worker 终态 `DELIVERY_INTEGRITY`）；包内
  `www/scene/native.json` 换成**交付的那一份字节**（引擎写的是 pretty 副本，语义同、字节不同）；
  清单改为"引擎元数据 + 逐文件 SHA256 + `package_sha256`"合并版，缺元数据键直接报错不补默认值。
  工具层 `build_package` 与 `Chain.packaging` 都调它，`worker/steps.py` 的 `scene_bytes` 别名随之删除。
- **抓到的漏检**：逐文件表原先按文件名排除清单自身，而上游 dist 里真有嵌套同名交付物
  `www/simulator/manifest/manifest.json` ⇒ 它一直被排除在哈希表外。实测整包 2163 个文件，
  旧规则只登记 **2161** 条，改为按完整路径排除后 **2162** 条。
- **行为改动（如实记账）**：一次发布登记的产物从 1 份变 2 份（`native.json` + 离线包 `manifest.json`），
  `test_chain_worker.py` 两处 `art_count == 1` 改为 2 并补上包内字节与清单的核对；
  这不是放宽，是把以前没交付的东西真正交付了。
- 计数：新增 `tests/python/test_package_builder.py`（7 项，假引擎客户端，把构建器自己的职责钉住，
  含篡改后磁盘重算摘要、缺元数据必须拒、坏字节重写不发）；pytest 125→**132**（131 通过 / 1 SKIPPED），
  vitest 仍 **70**（本轮未改 TS）。
- **C.5 只落地一半**：`offline_package.index_present` 仍然只证明"入口文件在盘上"，
  发布前**没有浏览器实测**，"这份包在 Chromium 里真能跑出光路"这条还没证据，所以 `ready` 一词没写进任何结论；
  发布后的下载重验只在测试里做，运行时链路还没做。这两条连同 C.3/C.6/C.7 仍是未闭环项。

## 8. 实况（同第四轮，起点 `cba81a1`）：C.5 的浏览器实测闸门接进发布链

§7 末尾写的"C.5 只落地一半"，本轮补上发布**前**那一半：

- 新增 `services/engine-host/src/verify/offline-runner.ts`（214 行）+ `POST /verify/offline_package`：
  读包内清单的 `entry` → 起一个只绑 `127.0.0.1` 的随包静态服务 → 真 Chromium 打开 → 7 条判据 → 关服务关浏览器。
  判据是「入口声明 / 入口在盘 / 场景载入 / 画出光斑 / 零出网 / 无页面错误 / 截图成功」，
  任一不过 `ok=false`，且 422 也把逐项判据带回去（不把细节压成传输错误）。
- `PackageBuilder` 在建包最后一步调用它：不过就抛 `DeliveryIntegrityError(code="OFFLINE_NOT_RENDERED")` ⇒
  **拿不到包也就发布不出去**；实测结论写在 `revisions/<候选版本>/offline_verification.json`（不进逐文件哈希表：
  它是关于包的观测，不是包的内容）。引擎客户端不认识这个方法时直接拒绝，不默认通过。
- `Chain.packaging` 的终态码改为保留异常自带的 code，"包打不开"与"清单核对不上"在报表里不再同名。
- 实测数字（f=15、u=30）：光强 287776335、点亮像素 453202、canvas 名录 6 个（含 `canvasLight`）、
  零出网、无页面错误，单次 9.2–10.2 秒。反面：删掉 `www/simulator/main.js` 后 `scene_loaded` 与
  `rays_rendered` 同时不过——页面仍"能打开"，所以这条正是 `index_present` 的盲区。

  `frameLocator(...).isHidden()` 判"场景已载入"，而 Playwright 在元素不存在时同样返回 true，
  所以 iframe 加载失败也报绿。我试着在同一处加 canvas 计数，该用例直接 180s 超时，遂回退改动只留登记；
  新测试用的是"遍历 frame 树、要求元素存在"的写法。
- 计数：vitest 70→**74**（新增 `tests/e2e/package_verify.test.ts` 4 项，含控制组），
  pytest 132→**135**（`test_package_builder.py` 7→10 项）。全量 exit 0。

  C.7 预览 origin 与 postMessage 校验未动。另有两处父层 README 的目录登记本轮**故意没写**
