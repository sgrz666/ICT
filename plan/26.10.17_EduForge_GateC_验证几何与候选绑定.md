# 26.10.17 EduForge — Gate C 开工：验证报告绑候选 + 特殊工况改为实测几何

> 触发：指令 §2 Gate C。**本轮只推进 C.1 与 C.2**，并且把一条「假绿灯」换成了「真拒绝」——
> 因此 Gate C **未闭环**，本文写清楚已经落成什么、量具极限在哪、还差什么。
> 分支：`main`（用户 2026-10-17 定口径：以后所有改动直接落 main，不建分支）。起点 `0573ea1`。

## 1. 本轮实施（C.1 + C.2）

### C.1 验证报告绑定候选、来源与剖面

- `validation/reports.py`：`Check` 增加 `source`（证据来源）、`profile`（成立剖面）、
  `status`（`pass`/`fail`/`na` 三态）、`tolerance`（容差依据）、`decisive`（是否参与结论）；
  `ValidationReport` 增加 `candidate_id`/`content_hash`/`engine_version`/`profile`；
  `finalize()` 改为：**任一 `fail` → failed；任一决定性 `na` → inconclusive；全 `pass` → passed**。
  `passed` 与 `status` 不一致时构造即报错，防止报告与结论各说一套。
- 迁移 `0003_validation_report_binding.sql`：`validation_reports` 加 `candidate_id`/`content_hash`/
  `engine_version`/`profile` 四列，全部可空、不改写老行（`Publisher.record_report` 现在写这些列——
  只存在 checks JSON 里的绑定等于没有绑定）。
- 工具层 `run_validation` 新增**只对后端开放**的 `final` 参数（`RunValidationInput` 不含它，模型碰不到）：
  `final=True` 时先把候选从库里**重新读回来**、再 `freeze()`，然后才出结论。Worker 的 validating 阶段用它。
  这条存在理由是「最终验证必须验的就是被冻结被发布的那一版」，不能吃进程内缓存。
- `Chain.validating` 的 payload 现在区分 `failed_checks`（观测反驳）与 `unverifiable_checks`（观测不到）——
  两者都拦得住发布，但混在一起会让人以为物理不成立。

### C.2 虚像与无穷远改为独立几何证据

- 引擎侧新增 `beamGeometry()`（`services/engine-host/src/adapters/ray-optics/upstream.ts`）：
  拿 7 块屏的**实测光斑二矩宽度**做线性拟合，给出四态
  `real`（两侧宽度收敛，交点即像面）/`virtual`（宽度单调增大且反向延长交点在入射侧）/
  `collimited`（宽度全程变化 < 15%）/`inconclusive`（附理由），
  并一并交出 `resolution_cm`（最小屏间距的一半）、`array_span_cm`、`fit_r2`、
  `resolvable_max_abs_distance_cm`。`Probe` 加了 `centroid_units`/`x_units`/`extent_units`。
- **孔径截断判据**：探测器均匀照亮时 rms 的理论上限是 `len/√12`；最窄读数超过它的 90%
  就说明光斑比屏还大，发散与平行在这块屏上根本读不出来 → 判 `inconclusive`，
  **不许把「看不出变化」说成「测得平行」**。
- `validation/policies.py`：删掉 `virtual_image_valid: u < f` 与 `focal_parallel_beams: abs(f-u)<1e-4`
  这两条公式恒真判据；新增 `beam_geometry_agrees`/`beam_geometry_resolved`/`beam_parallelism_observed`。
  实像工况另有决定性观测（屏位 + 光斑是否真聚焦），所以那里的几何 `na` 标为非决定性；
  虚像与无穷远没有别的量具，那里的 `na` 直接决定结论。
  顺带修掉 `image_plane_matches_reference` 的 `abs(...) < 1e-9` 假精确，改为「落在屏分辨率 2cm 内」。

## 2. 实测结果（本机，无 Docker；引擎为真实上游 bundle）

| 工况 | 引擎实测几何 | 报告结论 | 含义 |
|---|---|---|---|
| f=15、u=30（实像 v=30） | `real`，交点 30.86cm，R²=0.92 | **passed** | 与独立参考差 0.86cm ≤ 分辨率 2cm，且最窄屏 rms 0.92 真聚焦 |
| f=12、u=30（实像 v=20） | `inconclusive`（右侧两点拟合 R²=0.78） | **passed** | 靠屏位与聚焦两项决定性观测；几何作非决定性证据，如实标 `na` |
| f=30、u=30（u=f） | `collimated` 前置判定 → 实际落在 `apertureLimited` 分支 | **inconclusive** | 7 屏读数 rms 67.76 ≈ 均匀上限 69.3（98%），光斑铺满探测器，测不出平行度 |
| f=40、u=30（虚像 v=−120） | 同上，孔径截断 | **inconclusive** | 旧实现此处凭 `u<f` 报 passed，现为拒绝 |
| f=50、u=10（虚像 v=−12.5） | 同上（宽度只变 5.2%） | **inconclusive** | 期望「近虚像可测」被实测否证：发散角太大反而全部溢出探测器 |
| f=5（v=6 → 屏阵列之外） | `inconclusive` | **failed** | `spot_is_actually_focused` 反驳（最窄 rms 44.6 > 15） |

- 全量：`uv run pytest -q` **exit 0**，125 收集 / 124 通过 / 1 SKIPPED（真模型无 key）；
  `vitest run` **67 passed（10 files）**，含新增 `beam_geometry.test.ts` 13 项。
- 中途一次自我纠正：我一开始给「近虚像」写了应当通过的断言，实测发现 7 格屏在读数饱和时
  连 5cm 外的虚像都测不出来——**改的是判据与量具，不是改断言迁就绿灯**。

## 3. 本轮刻意收紧带来的行为变化（不是回归）

`test_chain_worker.py` 里两条旧用例（`test_chain_focal_parallel_beams_at_infinity`、
`test_chain_virtual_image_valid`）与 `test_agent_tools_acceptance.py` 的边界用例，此前断言的是
「虚像/无穷远任务发布成功」。那个成功建立在公式自证上，现已不存在，因此改为断言：

- `test_chain_far_virtual_image_is_refused_with_stated_instrument_limit`：任务可见失败
  （`VALIDATION_NOT_PASSED`）、head 不动、无产物；
- `test_chain_parallel_beam_must_be_measured_not_assumed`：只允许两种结局——
  实测到平行度而发布，或测不出来而拒绝，**不允许凭公式发布**。

## 4. Gate C 还差什么（未闭环，别当已完成）

1. **C.2 的量具缺口**：要在教学上真正覆盖虚像与无穷远，必须给验证换成能测出**出射光线方向**的观测量——
   要么读上游 Simulator 的光线折线（`Ray`/`Light` 数据，本轮未探明其无头可用性），要么加宽/加密屏阵列
   （改 `catalog/templates/optics/convex-lens/` 的探测器几何，会牵动 54→67 项 TS 基线与离线包）。
   在补上之前，虚像/无穷远一律不发布，这是**已知功能缺口**而非「已完备」。
2. C.3 `teaching_views.json` 真被 UI 读取与导出（Chromium 实测）；`view_registered_*` 只代表登记合法。
3. C.4 统一 PackageBuilder（Worker 目前仍不建离线包，只有工具层建），逐文件 SHA256 + 整体摘要 + 浏览器实测后才允许发布。
4. C.5 Publisher 核对浏览器结论与下载重验 manifest；种子版本的可信预览。
5. C.6 案例库导入实装 2–3 个（`handleImportToStudio` 现在会静默换成凸透镜模板，属必须修的项）、其余标只读。
6. C.7 预览独立 origin + postMessage 精确校验（`PreviewFrame.tsx` 仍是同源且 allow-scripts+allow-same-origin）。
