## 1. 核心问题与实施项

根据最新实施指令（2026-10-17 后续实施指令_Agent执行版 §2 Gate C.0）：

1. **解决候选冻结并发竞态窗口**：
   - `CandidateRepository.write` 原 SQL 缺少 `status = 'editing'` 约束，在多连接交错下，旧写入（迟滞抵达）以相同的 `state_version` 成功执行并重置 `status='editing'`，重新打开已冻结的候选；
   - 修复：在 `write()` 的 `WHERE` 谓词中追加 `status = 'editing'`，并在 CAS 失败诊断中识别已被冻结/发布状态抛出 `CandidateFrozen`；
   - `freeze()` 约束 `status in ('editing', 'frozen')` 保证幂等且防篡改；
   - `bind_validation()` 约束 `status in ('editing', 'frozen')` 且内容哈希匹配；
   - `rebase()` 约束 `status in ('frozen', 'published')` 推进基线并恢复编辑状态。

2. **Node Engine Host 内部接口路径沙箱与资源防御**：
   - 新增 `code/eduforge/services/engine-host/src/security/path-sandbox.ts`，定义受控沙箱目录白名单（`EDUFORGE_ARTIFACT_DIR`, `output/eduforge/candidates`, `tmpdir()`），校验输入绝对路径与符号链接解析（`realpath`）；
   - `POST /export/offline_package` 与 `POST /verify/offline_package` 端点应用 `assertWithinSandbox()`，越权即报 HTTP 403 `FORBIDDEN`；
   - `readBody()` 限制 10MB 请求体，超限报 HTTP 413 `PAYLOAD_TOO_LARGE`；
   - `verifyOfflinePackage()` 严格校验 `manifest.entry` 必须为相对路径且规范化后严格落在 `www/` 子目录下；
   - 随包静态服务请求监听器改用标准 `new URL(req.url()).origin` 严格全等比对，修复前缀假同源风险。
