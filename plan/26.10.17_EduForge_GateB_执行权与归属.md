**修复前根因（精确到函数/调用链）**

1. **「有心跳」只是文档说法**：`worker/lease.py::LeaseManager._heartbeat_loop` 调 `repository.heartbeat(...)`，而 `JobRepository` 从来没有这个方法（只有 `renew_lease`）——照现状接线会 `AttributeError`；`renew_lease` 本身零调用者。默认 90s 租约，真模型多轮必然超时。
2. **续租守卫太弱**：旧 `renew_lease` 是 `where id=$1 and lease_token=$2`，既不看 `status` 也不看 `lease_until` 是否已过期，因此「先睡过期、再自己续回来」合法。
3. **重试无记账**：`CLAIM_SQL` 不写 `attempt`；`next_run_at` 只在 DDL 里存在；任何非终态异常从 `run_once` 直接穿出，任务停在 `running` 等租约过期，没有退避也没有上限。
4. **`job_events` 序号会撞**：`append_event` 用「先 `max(sequence)+1` 再 insert」两条独立语句，同一 job 并发追加会主键冲突并丢事件。
5. **身份与归属形同虚设**：`api/main.py` 的中间件无条件写死 `request.state.owner_id = LOCAL_DEV_OWNER`；`JobService.get`、`ExperimentLookup.get`、`/revisions`、`/revisions/{id}/artifacts`、`/artifacts/{id}/download` 都只按 UUID 查，**任何知道 id 的人都能读别人的实验与产物**；`submit` 不校验实验归属，也不校验 `base_revision` 是否属于该实验/是否为当前 head。
6. **工具层缺版本归属条件**：`open_experiment` 读版本用 `where id = $1`，缺 `AND experiment_id = $2`；查不到时静默沿用模板场景（把别人的版本「洗」成一份干净新场景）。`search_experiments` 列实例时不带 owner。
7. **发布幂等只看 UUID**：`JobRepository.publish` 见 `experiment_revisions.id` 已存在就 `return`，不核对它属于哪个实验/父版本/job，也不核对字节——换个内容也能顶着同一个版本 id 宣布「已发布」。
8. **本轮实测新抓到的（最重要的）一条**：Runner 构造 `JobContext` 时**回读 `jobs.lease_token`**。被抢权的旧 Worker 于是拿到新主人的 token，`renew_lease`/发布守卫全部对它「合法」——执行权凭据的来源错了。`test_two_workers_cannot_double_publish` 第一次跑就抓到这个（旧 Worker 一路跑到 packaging）。

**实现方案与为何没有重建一套并行系统**

- 沿用既有组件：`LeaseManager` 是原来那个类（改实现、改调用点），`JobRepository` 是原来那个仓储（加 `renew_and_check`/`retry_later`），发布仍是 `JobRepository.publish` 那**一条**事务——`test_single_publish_path.py` 的结构守卫继续成立，没有出现第二个租约组件或第二条发布路径。
- 执行权判定只有一处真源：**SQL**。`renew_and_check` 回报状态词；工具层 `_assert_execution` 与 `Chain._check_execution` 都读它，不再有 Python 侧的「我以为我还活着」。
- 心跳必须用**池里的另一条连接**：asyncpg 单连接不允许并发查询，与 Agent SQL 共用会互相打断；`make_worker(pool=…)` 显式区分「有心跳的生产」和「无心跳的单测」。
- 身份是**边界而不是认证**：默认保留开发身份以便本机与测试照跑，`allow_dev_identity=False`（或 `EDUFORGE_ALLOW_DEV_IDENTITY=0`）后要求 `X-Owner-Id` + `X-Gateway-Token` 与 `EDUFORGE_GATEWAY_TOKEN` 相符。真实认证仍在赛题侧（AgentArts 那条），本层只保证「不许把内部身份当默认」。

**数据库迁移 / 向后兼容性**：本轮没有新增列（`attempt`、`next_run_at`、`lease_token`、`lease_until`、`jobs.candidate_revision_id` 都在既有 schema 内），`schema_migrations` 仍是 0001/0002；所有新 SQL 对旧库直接可用。

**新增的负向测试与故障注入证据**（`test_gate_b_execution_rights.py`，11 项）

1. `test_heartbeat_keeps_lease_and_control_group_proves_it`：3.5s 的规划 + 1s 租约——有心跳时并发 thief 领不走且 `renewals >= 2`；**控制组**（不给池）同一任务在租约到期后被抢走、`attempt >= 2`。
2. `test_stolen_lease_blocks_writes_and_publish`：库里把 `lease_token` 改掉 → `beat()` 回报 `stolen` → 下一次 `apply_scene_patch` 抛 `LEASE_LOST`，场景读数仍是 15.0（**没有第二次写入落进候选**）；旧 Worker 再去发布被事务拒绝，`experiment_revisions` 仍是 1。
3. `test_cancelled_job_stops_the_chain_and_cannot_publish`：`status='cancelled'` → 守护器回报 `cancelled`、`check_active()` 抛 `JOB_CANCELLED`；绕过守护器直接调发布事务也被 SQL 挡住。
4. `test_attempt_is_accounted_and_backoff_bounds_retries`：两次领取 attempt = 1→2；`retry_later` 回 `queued` + `next_run_at` 在未来 + 记 `RETRY_*`，退避期内领不到；attempt 置 9 后 `run_once` 终态 `MAX_ATTEMPTS_EXCEEDED` 且 `status='failed'`。
5. `test_event_sequence_is_unique_under_concurrent_append`：池内 12 条连接并发追加 → 序号恰为 1..12、事件 12 行（修复前会主键冲突）。
6. `test_publish_replay_checks_the_bytes`：同一版本 id 同内容重放 → 幂等、不多出版本；换内容抢同一 id → `RevisionConflict`。
7. `test_publish_refuses_foreign_identity`：拿 A 的 job 发 B 的实验 → `OwnershipConflict`。
8. `test_open_experiment_rejects_foreign_revision_and_search_is_scoped`：同 owner 的另一实验的版本 → 拒，且**不留工作态**（不回落到默认模板）；检索面不含他人实例。
9. `test_cross_owner_api_access_is_refused`：B 读 A 的实验/任务/版本/取消/回滚/提交 → 404/404/空/404/404/404；A 自己 200；过期 base → 409。
10. `test_fixed_dev_identity_can_be_disabled`：关掉开发身份后无凭据 → 401 `IDENTITY_REQUIRED`，带正确凭据 → 正常，模板清单仍免身份。
11. `test_two_workers_cannot_double_publish`：A 无心跳跑到一半被 B 接管 → 最终**只有一个新版本**、native 产物一份、job `succeeded`，A 可见地失败为 `LEASE_LOST`。
