# 知识检索 Agent（RAG 里的 R）

给六学科 31 个场景各配了一套本地知识库（共 155 个文件 / 359 个片段 / 31 个主题 / 5 个类别），并写了一个检索 Agent：
**需求 JSON → 识别主题 → 6 条检索式 → 多路召回 → 融合排序 → 结构化知识包**。

零第三方依赖，纯 Python 自带库，`python` 直接跑。

## 一、目录

```
02_retrieval_agent/
├── knowledge/                  知识库原文（Markdown，改了立刻生效）
│   ├── 01–05_*.md              电路：课标 / 教材 / 规范 / 安全 / 交互
│   ├── 06–10_浮力_*.md          浮力：同上五类
│   └── 011–155_主题_类别.md     六学科 29 个主题 × 5 类（自动生成，勿手改）
├── seed/                       知识库源数据与生成脚本
│   ├── math_kb.py 等 6 个       学科源数据：课标/教材/规范/安全/交互 + 关键词 + 单位 + 公式
│   ├── build_kb.py             渲染 knowledge/*.md；--check 只体检
│   ├── build_topics.py         生成 ../topics_extra.py（29 个 PROFILE）
│   └── check_kb.py             自检：主题识别 / 类别覆盖 / 跨主题污染
├── kb.py                       加载 → 按主题切块建模 → BM25 检索
├── retrieval_agent.py          检索 Agent 主程序
├── ../topics.py                主题配置（关键词 / 检索侧重 / 单位 / 阈值），02 和 04 共用
├── ../topics_extra.py          29 个新主题的配置（自动生成，被 topics.py 自动合并）
└── output/知识包_xxx.json       下游生成 Agent 的输入
```

知识库要改内容，改 `seed/*_kb.py` 后重跑 `build_kb.py`，别直接改 `knowledge/`——原因见 `seed/README.md`。

## 二、跑起来

```bash
cd 02_retrieval_agent

python kb.py                    # 自检：看切块结果，两个主题各试一条查询
python retrieval_agent.py       # 用内置示例需求跑（电路）
python retrieval_agent.py --req ../01_single_agent/output/需求_xxx.json   # 接上一阶段
python retrieval_agent.py "生成一个探究浮力大小与排开液体体积关系的浮力实验"
python retrieval_agent.py --topic 浮力 ...                                # 手动指定主题
python retrieval_agent.py --topk 8                                        # 控制知识包大小
```


## 三、它到底"Agent"在哪

普通搜索是"一句话进、一堆链接出"。检索 Agent 多了三步判断：

| 步骤 | 做了什么 | 为什么必须有 |
|---|---|---|
| ⓪ 主题圈定 | 按关键词长度加权，从需求文字判断属于 31 个主题中的哪一个，只在该主题的知识里检索 | 三十多个实验的材料混在一起时，"实验 规范"这类查询会把别的实验规范也召回来，知识包就串了 |
| ① 查询规划 | 把需求 JSON 拆成 6 条检索式：主题 / 主题细节 / 变量 / 实验规范 / 安全 / 交互 | 一条查询只能覆盖一个语义方向，"欧姆定律 电压 电阻"永远搜不到安全规范 |
| ② 多路召回 + 融合 | 每条检索式各取前 8，用 RRF + 查询内相对得分混合排序 | 不同查询的分数量纲不同，不能直接相加；只说"命中几条"又会埋掉精准的单路结果 |
| ③ 组装知识包 | 按 5 个类别归档，每类至少保 2 条 | 下游生成 Agent 需要的是"可直接使用的知识"，不是一堆散装段落 |

第 ⓪ 步是加第二个实验时才暴露的问题：知识库变大不等于变好。
两套材料放在一个索引里，`浮力` 的查询会命中"学生易错点""安全提示"这类两边都有的通用片段，
生成出来的页面就会出现"用滑动变阻器测浮力"这种缝合怪。所以 `kb.py` 里每个主题各建一份 BM25 索引。

第 ② 步是重点，也是我踩过的坑：第一版只用 RRF，结果"实验规范"整类被挤出去了——
因为"学生常见错误"这种通用片段被 5 条查询同时命中，分很高；而"电表的使用"只被 1 条查询命中。
加入 0.5 权重的"查询内相对得分" + 类别保底之后才正常。

## 四、为什么不用向量库

知识库只有几千字时，BM25（关键词算法）和向量检索的效果差不多，但向量要多三步成本：
装包、调 embedding 接口、按 token 付费。所以先用 BM25 跑通，中文靠"相邻两字成词"绕过分词库。

**什么时候该换成向量**：知识库超过几万字、或者用户会用完全不同的说法问同一件事
（"电流跟电压啥关系" vs "I-U 图像斜率含义"）。那时在 `KBsearch()` 那里换实现即可，上层代码不用动。

## 五、扩充知识库（加第三个实验）

只要往 `knowledge/` 里丢 md 文件就行，格式约定：

```markdown
---
类别: 实验规范          # 决定它进知识包哪个抽屉（5 个类别之一）
主题: 浮力              # 决定它属于哪个实验，检索时按这个隔离
来源: 人教版八年级物理    # 会写进 citations，答辩时用得上
---

## 章节标题
正文……
```

规则：`---` 之间必填 `类别`、`主题`、`来源`；每个 `## ` 是一个片段；单段超过 420 字会自动按段落切分。

**加第三个实验的完整步骤（两步，不用改任何代码）：**

1. 在根目录 `topics.py` 的 `PROFILES` 里加一条，填五个字段：

| 字段 | 作用 | 例子（浮力） |
|---|---|---|
| `关键词` | 从需求文字认出主题 | 浮力、阿基米德、排开、浸没 |
| `检索侧重` | 把"规范/安全/交互"翻译成这个实验的行话 | 实验 规范 器材 弹簧测力计 溢水杯 步骤 |
| `单位组` | 审查时该看到哪些单位 | 力 N、密度 kg/m³、体积 m³ |
| `数值上限` | 超过就有安全隐患的阈值 | 力不超过 20 N |
| `公式示例` | 写进生成提示词与审查建议的标准写法 | F浮 = ρ液 g V排 = 1000 kg/m³ × 10 N/kg × 0.0002 m³ = 2.00 N |

2. 在 `knowledge/` 放 5 个 md（对应 5 个类别），`主题` 写同一个名字。

**为什么措辞必须放在配置里**：查询式如果写死成"接线 电表 滑动变阻器"，浮力实验去搜这串词会全落空，
检索 Agent 会退化成"搜不到东西的搜索框"。这也是我加第二个实验时踩到的坑。

老师的课件拿到后，转成这样的 md 丢进去即可。

## 六、四个可调参数

| 参数 | 位置 | 默认 | 调大的后果 |
|---|---|---|---|
| `per_query` | `retrieve()` | 8 | 每路召回更多，噪声变多 |
| `final_k` | `main()` 的 `--topk` | 12 | 知识包更全，但塞给生成模型的上下文变长 |
| `per_cat_min` | `retrieve()` | 2 | 冷门类别也能进，但可能带进弱相关片段 |
| `0.5 / 0.5` | `retrieve()` 里的权重 | 各半 | 偏 RRF＝更重通用性，偏 rel＝更重精准度 |

## 七、怎么接下一步

生成 Agent 直接读 `output/知识包_xxx.json` 里的 `knowledge_pack`：

```python
prompt = "请根据以下需求生成单文件 HTML 实验：\n%s\n\n必须遵守的规范：\n%s" % (
    json.dumps(req, ensure_ascii=False),
    "\n".join(it["要点"] for cat in ("教材内容", "实验规范", "安全约束")
              for it in pack[cat]),
)
```

`citations` 字段留着别删——作品分享帖和答辩里"你的知识从哪来"这个问题，就靠它回答。

## 八、搬到 AgentArts 平台上怎么做

本地这套是"草稿"，平台上是"成品"：

1. 把 `knowledge/*.md` 上传到 AgentArts 知识库（平台会自动切块、向量化）。
2. 工作流里加一个"知识检索"节点，选这个知识库，查询内容接"需求理解"节点的输出。
3. `retrieval_agent.py` 里的 6 条检索式，改成节点里的"检索意图"或多查询配置。
4. 平台检索结果和本地的 `knowledge_pack` 结构对齐后，生成节点可以原样复用。

## 九、常见问题

- **搜不到想要的内容**：先在 `kb.py` 里跑自检，看那个知识点有没有被切成片段；没有就是知识库缺内容，不是算法问题。
- **结果太泛**：把 `--topk` 降到 8，或把 `per_cat_min` 调回 1。
- **同一片段重复出现**：`build_pack` 已按 id 去重；如果换了向量检索，记得保留这一步。
