# 教学实验生成 Agent —— 项目总览与流水线使用说明

一句话：老师给一句需求 → 产出一份**离线可运行、经过质检**的交互式教学实验 HTML。

## 一条命令跑全流程

```bash
python run_pipeline.py                                # 用内置示例需求（电路）
python run_pipeline.py "生成一个浮力实验"               # 提自己的需求
python run_pipeline.py "..." --max-rounds 3 --open     # 最多返工 3 轮，结束后打开结果
python run_pipeline.py "..." --template-only           # 不调模型，只验证链路
```

目前有两个端到端验证过的实验场景：

| 场景 | 需求示例 | 最近一次成绩 |
|---|---|---|
| 电路（欧姆定律） | "生成一个可以改变电阻和电压的电路实验" | 90.9 分，1 轮通过 |
| 浮力（阿基米德原理） | "生成一个探究浮力大小与排开液体体积关系的浮力实验" | 100 分，2 轮通过 |

需要先在 `01_single_agent/.env` 里配好 `LLM_API_KEY`（本地调试用 DeepSeek，比赛期换华为云 MaaS 只改三行）。

每次运行在 `runs/时间戳/` 下生成完整档案：

| 文件 | 内容 |
|---|---|
| `01_需求.json` / `02_知识包.json` | 前两个角色的产物 |
| `0N_草稿_模型输出.html` | 每一轮模型生成的原始版本 |
| `0N_审查报告.json` | 每一轮的质量审查报告 |
| `交付_教学资源.html` | **历史最高分**那一版（不一定是最后一版） |
| `运行日志.json` | 全部阶段耗时、命令、退出码 |
| `运行报告.md` | 人能直接看的总结，答辩/写帖直接用 |

## 四个角色 + 一个编排器

| 目录 | 角色 | 本质 | 产物 |
|---|---|---|---|
| `01_single_agent/` | 需求理解 | 大模型 + 提示词 → 结构化 JSON（8 字段） | `output/需求_*.json` |
| `02_retrieval_agent/` | 知识检索 | 按主题隔离的 BM25 多路召回 + 类别覆盖，**不用模型** | `output/知识包_*.json` |
| `03_generator_agent/` | 工具生成 | 大模型写单文件 HTML，清洗→校验→修复→兜底 | `output/教学资源_*.html` |
| `04_review_agent/` | 质量审查 | 规则检查 + 无头浏览器真实操作页面 | `output/审查报告_*.json` |
| `run_pipeline.py` | 编排器 | 子进程调度 + 返工循环 + 运行档案 | `runs/` |
| `topics.py` | 主题配置 | 关键词 / 检索侧重 / 单位 / 阈值 / 公式示例，02 与 04 共用 | — |

**为什么编排器用子进程而不是 import**：01 和 03 都有 `prompts.py`，import 会互相覆盖；子进程天然隔离，也和 AgentArts"每个节点独立调用"的形态一致。

**返工循环**：审查不通过 → 修改意见回传生成环节 → temperature 从 0.7 降到 0.3 重写 → 再审。最多 `--max-rounds` 轮，交付历史最高分版本。

## 已知边界（答辩要主动说）

1. **知识库覆盖"电路"和"浮力"两个实验**，其余主题（大气压、机械能等）要先按 `02_retrieval_agent/README.md` 第五节补两样东西：`topics.py` 加一条配置 + 5 个知识 md，代码零改动。接老师课件后照此批量扩充。
2. **模型生成的页面仍可能有死按钮**。浮力交付页中"水 1.0 g/cm³"和"复位"两个按钮在已处于该状态时点击无变化（审查已列出）；这是"重复选择当前状态"，不是功能缺失，但演示前最好知道。
3. **审查器只判断"有没有、能不能跑、算没算错"**，不评价教学法优劣。
4. 生成 HTML 有 12000 字符篇幅预算 + 自动续写兜底，因为 DeepSeek 单次输出上限 8192 token，超长会被截断。

## 调试过程中的关键教训（都是真踩过的）

- 纯 RRF 检索会整类挤掉"实验规范"，要用 `0.5×RRF + 0.5×相对得分` + 类别保底。
- `sys.path.insert(0)` 会让 01 的 `prompts.py` 覆盖 03 的同名文件，要 append。
- 需求与知识包要按文件名配对，"取最新"会错配。
- 不设 `max_tokens`，长 HTML 一定被截断，而且接口不报错，只能靠 `finish_reason` 发现。
- 审查器必须"像老师一样操作页面"：先点开关再读数，否则会把断路时的 0 A 判成算错。
- 审查规则和生成要求必须对齐：要求页面展示代入式，就要在提示词里给出固定格式。
- **多主题改造时最容易翻车的三处**：① 检索不按主题隔离，两套知识互相污染；② 审查器把"本实验的公式"写死成 `I = U/R`，会把完全正确的浮力页面判死；③ 主题识别要看页面本身而不是需求文件，默认取"最新需求"会拿别的实验的需求来审页面。
