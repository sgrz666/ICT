# 共享场景库说明（六学科统一质感）

## 一句话

把「化学那版双烧杯为什么好看」的规则抽成代码：**主光左上、阴影右下，每个实体至少
渐变 + 高光 + 接触阴影，文字最后画并自动收边**。六科共用一套原语，各科只写自己的版面。

## 三层结构

```
frame/vis.js     原语层：玻璃容器 / 立体实体 / 光影 / 标注 / 光学元件
frame/<科>.js    场景层：该学科的固定版面（版面不再由模型即兴发挥）
页面 <script>    业务层：只给状态量、写 DOM 读数与代入式、写 __DATA__
```

`shell.py` 按学科自动内联需要的层，产物仍是**单文件、断网可跑**。
注入顺序固定：`vis.js` → `<科>.js` → 页面脚本。

## 现成版面一览

| 学科 | 库 | 调用 | 说明 |
|---|---|---|---|
| 化学 | `CHEM` | `CHEM.scene(cv,{p,V,leftSol,rightSol,formula})` | 双烧杯对比 + 方程式条 + 放大镜 |
| 物理 | `PHYS` | `PHYS.floating(cv,{objRho,liqRho,mode,sub,level})` | 烧杯 + 液体 + 物块 + 弹簧测力计 + 铁架台 |
| 物理 | `PHYS` | `PHYS.optics(cv,{u,f,scr,lensAt})` | 光具座 + 透镜 + 光屏 + 三条特殊光线 |
| 数学 | `MATH` | `MATH.cubeCut(cv,{a,theta,phi,t})` | 真 3D 正方体 + 橙色截面 + 地面阴影 + 拖动旋转视角（θ/φ/t 直接变换，3→6 边形连续变化） |
| 数学 | `MATH` | `MATH.funcPlot(cv,{a,b,c,domain,shade})` | 网格坐标 + 曲线 + 顶点 + 积分阴影 |
| 生物 | `BIO` | `BIO.microscope(cv,{mag,cells,stain})` | 圆形视野 + 细胞 + 目镜测微尺 |
| 地理 | `GEO` | `GEO.earth(cv,{tilt,season,spin})` | 地球 + 经纬网 + 晨昏线 + 太阳平行光 |
| 地理 | `GEO` | `GEO.profile(cv,{layers})` | 地层剖面（岩层 + 地表植被） |
| 信息 | `CS` | `CS.flow(cv,{nodes,edges,packet})` | 等距卡片 + 贝塞尔连线 + 数据包 |

每个函数都会把「装置：…」写进 `canvas[aria-label]` 和 `#tip`，
所以「烧杯 / 透镜 / 正方体 / 细胞」这些词一定会出现在页面文字里（J6 判据只读 DOM 文本）。

```js
VIS.mount(cv, {DW, DH});  VIS.clear();  VIS.wall({tableY, tone:'warm', props:true});

VIS.stand({x,baseY,topY});  VIS.rail({x0,x1,y,h,px});  VIS.post({x,y,base})
VIS.lens({x,y,h,bulge});  VIS.ray({pts,color,width,dash});  VIS.magnifier({x,y,r,draw})
VIS.pill({x,y,text,bg,size});  VIS.leader({x1,y1,x2,y2,dash});
VIS.card({x,y,w,title,rows});  VIS.panel({x,y,w,h});
VIS.arrow({x1,y1,x2,y2,h});  VIS.ruler({x,y,h,max,value});
VIS.text({x,y,text,size,weight,color,align,pad,stroke,onDark})
VIS.shadow(x,y,rx,ry,a);  VIS.hatch({poly,gap,color})
VIS.MAT 材质表 / VIS.mix / VIS.shade / VIS.rgba / VIS.clamp
```

三条硬规则：

1. `VIS.glass → VIS.liquid → VIS.glassFront` 必须按这个顺序，否则液体会盖住刻度。
2. 文字一律最后画；`VIS.text` 会自动把包围盒收进画布 8px 内。
3. 深色背景（星空、夜景）上的文字必须传 `onDark: true`，
   否则默认的白描边会把字糊成一个白块。

## 新增一个场景的步骤

1. 在对应 `frame/<科>.js` 里加一个 `function xxx(cv, cfg)`，开头 `VIS.mount` + `VIS.clear`。
2. 画背景 → 器材 → 标注（文字最后），全部复用 `VIS.*` 原语，不写裸 `fillRect`。
3. 在文件末尾的 `window.<科>` 上导出，并补一条 `auto()` 里的关键词判断（兜底用）。
4. 在 `03_generator_agent/prompts.py` 第九节第 9 条的表里加一行「需求关键词 → 库」映射。
5. 用 `tools/lib_gallery.html` 加一个 `?s=xxx` 分支截图验收。

## 质感怎么验收（不靠肉眼）

「真实度和立体度」被拆成 6 个可测量的量，全部是帧内比率，动画循环多帧也不会把数字冲淡：

| 指标 | 看什么 | 标准 |
|---|---|---|
| 渐变填充占比 | 玻璃、液体、金属的立体感来源 | ≥ 8.5% |
| 半透明叠层占比 | 玻璃质感（`VIS.glass` 的 rgba 叠层） | ≥ 5.5% |
| 立体件密度 | 径向渐变 + 椭圆 + 柔光阴影 / 填充数 | ≥ 10% |
| 曲线占比 | 圆角、弯月面、弧线；纯矩形堆砌会很低 | ≥ 55% |
| 色彩种类 | 24 色以下容易显灰 | ≥ 22 |
| 大面积纯色块 | `fillRect` 画 > 6000 px² 的不透明色块 | ≤ 6% |

审查器第 4 关的 **G4-08「画面具备立体质感」** 会在每次浏览器测试时自动量这三件事，
命中任意一条就判 FAIL 并给出改法：渐变/叠层双双接近 0（纯色贴片）、曲线占比 < 40%（矩形堆砌）、
大面积纯色块 > 15%（色块拼版面）。

实测基线（同一把尺子量出来的，可直接对表）：

| 页面 | 渐变 | 叠层 | 立体件 | 曲线 | 纯色块 | 判定 |
|---|---|---|---|---|---|---|
| 浮力（系统生成，调 `PHYS.floating`） | 32% | 52% | 17% | 89% | 2 处 | 通过 |
| 化学双烧杯（调 `CHEM.scene`） | 11% | 85% | 14% | 94% | 4 处 | 通过 |
| 凸透镜（调 `PHYS.optics`） | 28% | 22% | 14% | 92% | 1 处 | 通过 |
| 显微镜（调 `BIO.microscope`） | 97% | 98% | 1% | 100% | 1 处 | 通过 |
| 扁平对照页（纯 `fillRect` 拼的烧杯） | 0% | 17% | 0% | 0% | 50% | **FAIL** |

## 本次踩过的坑

- 用 `location.hash` 切换场景不会重新渲染（`goto` 只改哈希不重载），画廊测试改用 `?s=`。
- `ctx.filter = 'blur(3px)'` 的景深剪影会被误看成「画面竖条纹」，其实是背景圆柱剪影，
  在台面上方是正常的。
- 斜二测必须让 `y` 轴 45°、长度取 1/2（水平/垂直各 0.354），
  随便取 0.4/0.28 会把正方体画成压扁的盒子。
- 正方体的隐藏顶点是**后左下的 D 和后左上的 D₁ 两条**，隐藏棱只有 `A-D / C-D / D-D₁`；
  把 C 也当隐藏点会让六个面都画错。
- 光具座的第三条特殊光线（过 F 后平行出射）**不能参与「延长到最后一段斜率」的通用逻辑**，
  否则会从透镜斜着飞出画面。
- `v.clamp(cfg.sub, 0, 1)` 会让「浮力 > 重力」，物理上绳子已松弛；
  悬挂模式要 clamp 到 `ρ物 / ρ液`。
- 数字刻度、引线、胶囊标签必须手动布点：800 mL 刻度正好在液面附近，
  引线取物块下半部才不撞数字。
- 量「阴影」不能只看 `ctx.shadowBlur`：`VIS.shadow` 是用径向渐变画的柔光投影，
  只数 `shadowBlur` 会把立体感算成 0%，必须把径向渐变和椭圆一起计入「立体件」。
- 质感分不能跨学科套同一把尺子：几何作图（正方体）本来就没多少渐变，
  一律按分数评比会误伤，所以最终落地成「红线判定 + 分项实测值」，不做总分排名。
- J1 的 0 值误报：`F浮 = ρgV排 = 0` 时「显示 0、应为 0」被判成算错，
  容差判断不能写 `expect > 0`，要写 `isFinite(expect)` 并取绝对值。
- J1 的近似值误报：`一行细胞数 ≈ 800 / 600 = 1.3` 被判成 1.333 不一致，
  整句带 `≈`／`约` 时应按**显示位数的正确四舍五入**判，而不是按百分比容差。
- J1 的链式误判：`1.80 × 10 ÷ 10 = 1.80` 会被通用两数式截成 `10 ÷ 10 = 1.80` 报错，
  必须先跑三数链式解析并登记区间，通用式再跳过已被覆盖的片段。
- 正方体截面用**斜二测**画死了视角，页面上想「转一下看看」根本做不到，而且和样张里
  那版真 3D 的观感完全不同——所以 cubeCut 整段重写成 yaw/pitch 的 3D 变换 + 正交投影。
- 3D 投影必须**按包围盒自动缩放居中**：手写固定 `ox/oy/S` 时换个视角就会被画布切掉一角。
- 库接管页面画布时**不能 `cloneNode` 换掉旧节点**：页面闭包里还拿着那个 canvas，
  `cv.parentElement` 立刻变 null，`Cannot read properties of null (reading 'clientWidth')`。
  正确做法是旧画布 `display:none` 留在 DOM 里，旁边插一张新画布给库画。
- 接管后审查器要把隐藏画布排除掉，否则页面画在被隐藏画布上的字会被判成「被图元遮盖」。
- 库接管时**别直接覆盖 `window.__GEO__`**：页面自己还要读 `g.volumeA` 之类的字段。
  用 `Object.defineProperty` 拦截，页面写进 `PAGE_GEO`、库写进 `LIB_GEO`，
  对外读时返回合并体（以页面那份为底，覆盖成归一化口径）。
- 页面若用 `requestAnimationFrame` 重绘，库的重绘要排在它那一帧之后：`input` 里套两层
  `requestAnimationFrame` 再画，否则读到的还是上一帧的参数（画面与读数对不上）。
- 几何量对外统一折算成**单位立方体口径**（体积和 = 1.000、正六边形面积 = 1.299），
  否则 J4 会拿 a=2 的 8.000 去对 1.000 判失败。
