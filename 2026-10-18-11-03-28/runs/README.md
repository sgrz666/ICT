# 2026-10-18-11-03-28/runs — 端到端流水线运行现场档案

本目录存放教学实验生成流水线（`run_pipeline.py`）每次完整运行的现场归档快照。

## 目录职责与内容

- **职责**：保留每次实验生成的全部生命周期证据链，包括需求提取、知识召回、逐轮模型生成草稿、逐轮审查打分及最终评定。
- **单次运行目录结构**（以 `runs/<时间戳>/` 为单位）：
  - `01_需求.json`：需求理解角色生成的 8 字段结构化需求。
  - `02_知识包.json`：知识检索角色召回的相关教学规范与背景切片。
  - `0N_草稿_模型输出.html`：第 N 轮由大模型生成的原始页面代码。
  - `0N_审查报告.json`：第 N 轮由无头浏览器质检给出的分数与缺陷建议。
  - `交付_教学资源.html`：历史最高分版本的交付实验成品（不一定是最后一轮）。
  - `运行日志.json`：各阶段耗时、命令与退出码。
  - `运行报告.md`：可供答辩与分析直接使用的汇总总结。

## 与上下层的关系

- **上游**：`run_pipeline.py` 调度各子进程并在运行结束时自动创建时间戳目录并归档所有材料。
- **下游**：供质量分析、版本比对以及答辩材料整理使用。

## 已知的坑与纪律

- 逐次运行的现场档案体积较大且为运行时临时产生，根 `.gitignore` 中已通过 `2026-10-18-11-03-28/runs/*` 与 `!2026-10-18-11-03-28/runs/README.md` 进行规则排除，确保逐次档案不污染 Git 历史。
- 若要将某次标杆运行留入版本库，需在 `.gitignore` 中显式添加反向排除例外（如 `!2026-10-18-11-03-28/runs/<时间戳>/`）并按规范撰写说明。
